# 极地海洋环境信息平台需求文档

## 1. 文档信息

- 产品名称：极地海洋环境信息平台
- 代码标识：`polar-gis`
- 版本：一期需求基线 v1.0
- 状态：已确认
- 目标周期：12周
- 目标团队：1名前端、1名后端/GIS开发、1名测试兼产品支持

## 2. 产品定位

本平台面向极地及高纬海域的海图和海洋环境数据管理与浏览，提供数据导入、项目组织、地图发布、空间查询、属性查看和基础地图工具。

一期以 S-57 海图为正式支持标准，同时支持常见栅格和矢量地理数据。S-101、S-102只进行技术验证和接口预留。

本平台不是经认证的 ECDIS，不替代法定航海设备，所有页面、导出成果和打印成果均应保留相应免责声明。

## 3. 一期目标

1. 建立稳定的浏览器端海洋环境 WebGIS。
2. 实现 S-57 基础单元及连续增量更新的导入和发布。
3. 建立可复用的数据目录、项目和图层配置模型。
4. 为系统管理员提供数据导入、发布和故障查看能力。
5. 为普通用户提供专业、易用的地图浏览、查询、测量、打印和受控导出能力。
6. 支持常规地图和北极投影模式。
7. 使用演示数据验证 AIS 和水文气象适配接口。

## 4. 非目标

一期明确不建设：

- 多租户。
- 微服务和 Kubernetes。
- 手机端、平板专用界面和三维地球。
- 自动航线规划、航线风险优化和油耗计算。
- 生产级油污漂移模型。
- 实时 AIS、实时告警和大规模船舶时序存储。
- 完整 ECDIS/S-52 认证。
- S-101/S-102 生产级导入和表达。
- 在线绘制成果保存和复杂空间分析。
- 自动备份平台和重型可观测性平台。

## 5. 用户与角色

### 5.1 系统管理员

系统管理员可以：

- 创建、停用和重置用户。
- 管理系统管理员和普通用户角色。
- 创建、编辑、发布、归档和删除项目。
- 上传、导入、更新、停用和清理数据集。
- 配置图层分组、顺序、样式、透明度和默认显隐。
- 配置本地或在线底图。
- 查看导入任务、错误日志和审计日志。
- 预览草稿项目和失败图层。

### 5.2 普通用户

普通用户可以：

- 查看全部已发布项目。
- 查看项目中的可用图层。
- 临时调整图层显隐、透明度和前后顺序。
- 查询地图要素和属性表。
- 使用字段筛选和地图联动。
- 执行坐标拾取、距离测量、面积测量、截图和PDF打印。
- 导出允许的筛选结果为 CSV 或 GeoJSON。

普通用户不能上传、修改、发布或删除任何系统资源，也不能下载原始 S-57 文件。

## 6. 功能需求

### 6.1 认证与用户管理

| 编号 | 需求 |
|---|---|
| FR-AUTH-001 | 用户使用用户名和密码登录。 |
| FR-AUTH-002 | 登录成功后发放短期访问令牌和刷新令牌。 |
| FR-AUTH-003 | 支持安全刷新登录状态和主动退出。 |
| FR-AUTH-004 | 连续登录失败应受到速率限制。 |
| FR-AUTH-005 | 系统管理员可以创建、停用用户和重置密码。 |
| FR-AUTH-006 | 系统只有 `system_admin` 和 `user` 两个角色。 |
| FR-AUTH-007 | 所有受保护接口必须由后端执行角色校验。 |

### 6.2 项目管理

| 编号 | 需求 |
|---|---|
| FR-PRJ-001 | 管理员可以创建、编辑、发布、归档和软删除项目。 |
| FR-PRJ-002 | 项目包含名称、描述、封面、状态、初始范围、默认投影和创建信息。 |
| FR-PRJ-003 | 项目状态包括草稿、已发布和已归档。 |
| FR-PRJ-004 | 普通用户只能看到已发布项目。 |

| FR-PRJ-006 | 管理员可以预览草稿项目。 |
| FR-PRJ-007 | 删除项目不得删除其引用的数据集。 |

### 6.3 数据目录与上传

| 编号 | 需求 |
|---|---|
| FR-DATA-001 | 管理员可以上传 S-57、GeoTIFF/COG、Shapefile 压缩包和 GeoJSON。 |
| FR-DATA-002 | 单个上传文件最大5GB。 |
| FR-DATA-003 | 系统必须流式保存上传文件，禁止一次性读入内存。 |
| FR-DATA-004 | 系统校验扩展名、内容类型、压缩包安全性和文件完整性。 |
| FR-DATA-005 | 原始文件必须保留并关联到数据集版本。 |
| FR-DATA-006 | 数据集可以被多个项目复用。 |
| FR-DATA-007 | 数据集、版本、文件和导入任务必须可追溯。 |
| FR-DATA-008 | 数据集默认软删除；支持多选批量删除，逐项展示项目引用并拒绝删除仍被引用的数据集。物理清理由管理员专用页面执行，支持多选批量预览，须列出原始文件、派生表和GeoServer资源并输入确认文本。 |
| FR-DATA-009 | 管理员可以通过一个ZIP压缩包或浏览器本地目录选择一次提交多个S-57单元；单批次最多5000个直接上传文件、总量最大5GB。 |

### 6.4 S-57 导入和更新

| 编号 | 需求 |
|---|---|
| FR-S57-001 | 支持导入 S-57 `.000` 基础单元。 |
| FR-S57-002 | 支持按顺序应用 `.001`、`.002` 等连续更新。 |
| FR-S57-003 | 缺失中间更新、版本倒退或单元不匹配时拒绝更新。 |
| FR-S57-004 | 保存单元名称、版次、更新号、发布日期、比例尺和覆盖范围。 |
| FR-S57-005 | 通过 GDAL/OGR 转换并导入 PostGIS。 |
| FR-S57-006 | 导入失败不得污染当前有效版本。 |
| FR-S57-007 | 管理员可以查看更新历史并回退到上一有效版本。 |
| FR-S57-008 | 核心航海对象采用接近 S-52 的非认证表达。 |
| FR-S57-009 | 页面和输出明确标识“非认证航海显示”。 |
| FR-S57-010 | 批量导入自动识别每个`.000`基础单元，并将同名单元的`.001`及以后更新文件归组。 |
| FR-S57-011 | 新识别出的海图单元分别创建数据集和可追踪导入任务；批次不得将不同单元合并为一个数据集。 |
| FR-S57-012 | 同一单元严格按更新号串行处理；新单元必须包含`.000`，已有单元只允许追加当前更新号之后连续的更新文件。 |
| FR-S57-013 | 单个单元失败不得阻塞批次内其他合法单元，批次应保留成功、失败和部分失败结果。 |
| FR-S57-014 | 批量导入匹配到已有有效S-57数据集时，自动跳过已应用更新，仅追加连续的新更新；没有新更新时标记为已是最新。若历史源文件缺失且本次提供完整历史链，系统应修复可追溯源文件后再追加。 |

| 编号 | 需求 |

## 7. 非功能需求

### 7.1 性能与容量

- 最多200个账号。
- 支持50个并发在线用户。
- 支持500个已发布图层。
- 单个上传文件最大5GB。
- S-57批次直接上传最多5000个文件、总量最大5GB；ZIP最多10000个成员，解压后总量不得超过上传上限的4倍。
- 普通业务接口在正常负载下95百分位不超过2秒。
- 地图首屏在缓存命中且网络正常时不超过5秒。
- 属性查询默认最多返回1000条记录。

### 7.2 兼容性

- 支持桌面端最新版 Chrome 和 Edge。
- 最低分辨率1366×768，重点适配1920×1080。
- 不支持IE和手机端。
- 开发环境兼容Windows，生产环境为Linux。

### 7.3 安全

- 密码采用Argon2哈希。
- 凭据不得进入Git。
- 生产环境启用HTTPS。
- 上传文件必须经过安全校验。
- 所有管理操作由后端鉴权。
- 客户端错误不得包含内部堆栈、SQL或绝对路径。

### 7.4 可维护性

- 后端单体模块化，领域之间通过服务接口协作。
- 数据库变更必须使用Alembic。
- 核心业务代码测试覆盖率目标不低于80%。
- API、数据模型和UI行为变化必须同步更新文档。

## 8. 一期验收概览

一期验收必须至少完成以下端到端场景：

1. 管理员登录、创建普通用户，普通用户成功登录。
2. 管理员创建草稿项目并配置常规和北极投影视图。
3. 上传并成功导入一套 S-57 `.000` 数据。
4. 连续应用至少两个 S-57 更新文件并显示更新历史。
5. 上传并发布一份 GeoTIFF 和一份 GeoJSON。
6. 将多个复用数据集配置到项目，设置分组、顺序和默认显隐；验证每个S-57单元的内部对象图层自动纳入地图服务。
7. 发布项目后，普通用户可以浏览、查询、测量、打印和受控导出。
8. 普通用户无法访问管理接口和原始 S-57 文件。
9. 使用演示 AIS 和气象数据完成地图展示与选点查询。
10. 导入失败、图层失败和外部底图失败都有明确、可恢复的错误提示。
11. 通过ZIP或本地目录批量导入至少两个S-57单元，其中连续更新按单元归组；制造一个断档单元时，其他单元仍成功且界面显示失败项。

## 9. 依赖与假设

- 开发期间由使用者手动安装 PostgreSQL/PostGIS、GeoServer、GDAL 等第三方组件。
- 生产环境使用Linux和Docker Compose。
- 已有可用于开发和验收的脱敏 S-57 数据。
- 尚无正式 AIS 和水文气象数据源，因此一期仅提供适配接口与演示数据。
- 一期暂不实施自动备份，相关风险由项目负责人接受。
