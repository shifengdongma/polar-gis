# 极地海洋环境信息平台测试与验收方案

## 1. 测试目标

测试重点不是单纯覆盖页面，而是证明：

- 两个角色的权限边界不可绕过。
- 原始数据、版本和发布结果可追溯。
- S-57更新顺序和失败回退正确。
- 地图在常规和北极投影下稳定工作。
- 大文件和大属性表不会阻塞Web进程。
- 普通用户不会获得原始海图或管理能力。

## 2. 测试分层

### 2.1 后端单元测试

使用Pytest覆盖：

- 密码、JWT、刷新令牌和角色判断。
- 项目状态机和发布校验。
- 数据集级项目配置的当前版本过滤、物理图层展开、跨版本排除和管理员权限。
- 地图配置按数据集聚合多个内部对象图层，默认隐藏数据集不创建WMS图层，关闭后释放运行时图层。
- 数据集单项及批量软删除规则，包括混合引用项的逐项阻塞结果。
- 已删除数据集的资源清单、单项及批量确认文本校验、全量预检、分项提交和物理清理顺序。
- S-57更新号、版次和单元校验。
- 查询字段与操作符白名单。
- 存储键、路径规范化和上传安全校验。
- 任务状态转换和重试条件。

### 2.2 后端集成测试

使用真实PostgreSQL/PostGIS测试：

- Alembic从空库升级。
- 空间表写入、索引和范围查询。
- 任务领取并发。
- 数据版本原子切换。
- GeoServer REST使用隔离测试实例或可控替身。
- GDAL使用小型脱敏样本执行真实转换。

### 2.3 前端单元与组件测试

使用Vitest覆盖：

- 认证状态和令牌刷新。
- 角色路由和管理菜单。
- 项目、任务和图层状态组件。
- 筛选条件构建。
- 图层树搜索、显隐、透明度和临时排序。
- 演示数据和免责声明显示。

### 2.4 端到端测试

使用Playwright覆盖：

- 管理员登录、创建用户和退出。
- 普通用户无法访问管理页面。
- 管理员创建项目、上传小型样本并查看任务。
- 项目发布后普通用户进入地图。
- 常规和北极投影切换。
- 图层显隐、元数据、图例和定位。
- 要素识别、属性筛选、地图联动和导出。
- 距离、面积、截图和打印入口。

### 2.5 手工探索测试

重点检查：

- 大量图层的交互和错误隔离。
- 地图面板在1366×768和1920×1080下的可用性。
- 跨180度经线和高纬区域。
- 用户快速重复点击、刷新、返回和关闭页面。
- 导入中断、GeoServer停机和外部底图不可用。

## 3. 测试数据

仓库只允许小型、脱敏、可公开的测试数据：

- 一套可解析S-57 `.000` 样本。
- 对应至少 `.001` 和 `.002` 两个连续更新样本。
- 一个故意缺少 `.001` 的更新错误样本。
- 一个单元不匹配样本。
- 小型GeoTIFF、GeoJSON和Shapefile。
- AIS和水文气象演示JSON/CSV。

大型和受限数据放在仓库外，通过环境变量指定测试数据目录。

## 4. S-57专项测试

| 编号 | 场景 | 预期 |
|---|---|---|
| T-S57-001 | 导入有效 `.000` | 创建有效版本和可用图层 |
| T-S57-002 | 重复导入同一文件 | 识别重复并拒绝或复用，不重复建表 |
| T-S57-003 | 应用 `.001` | 更新号递增，当前版本切换 |
| T-S57-004 | 在 `.001` 后应用 `.002` | 成功形成新版本 |
| T-S57-005 | 直接向 `.000` 应用 `.002` | 返回 `S57_UPDATE_GAP` |
| T-S57-006 | 更新文件属于其他单元 | 返回 `S57_CELL_MISMATCH` |
| T-S57-007 | 版次不匹配 | 返回 `S57_EDITION_MISMATCH` |
| T-S57-008 | GDAL处理中失败 | 当前有效版本保持不变 |
| T-S57-009 | GeoServer发布失败 | 候选数据保留，图层标记发布失败，可重试 |
| T-S57-010 | 回退上一版本 | 当前版本和GeoServer资源正确切换 |
| T-S57-011 | ZIP或目录包含多个`.000`及更新 | 按单元归组，分别创建数据集和任务 |
| T-S57-012 | 同一单元包含`.000/.002`但缺`.001` | 该单元返回`S57_UPDATE_GAP`，其他单元继续 |
| T-S57-013 | ZIP不同目录出现同名单元同一更新号 | 批次拒绝重复更新号并展示失败原因 |
| T-S57-014 | 一个单元导入失败、另一个成功 | 批次为`partial_failed`，计数和失败项正确 |
| T-S57-015 | 批量包包含已有单元及更高连续更新 | 跳过已应用更新，仅创建新更新版本和任务 |
| T-S57-016 | 单元含`.000`至高编号连续更新 | 所有版本严格串行执行，当前更新号和任务数正确 |
| T-S57-017 | 批量包只包含已应用的更新 | 单元成功并标记`up_to_date`，不创建新任务 |
| T-S57-018 | 已有单元缺少下一连续更新 | 返回`S57_UPDATE_GAP`，不创建新版本 |
| T-S57-019 | 已有版本的历史源文件丢失但批次提供完整链 | 修复源文件后成功追加更新 |
| T-S57-020 | 已有版本的历史源文件丢失且批次未提供 | 返回`S57_HISTORICAL_SOURCE_MISSING`，不执行GDAL导入 |

专项核对核心对象：岸线、等深线、水深点、航道、助航标志、危险物、限制区和锚地。

## 6. 地图和投影测试

- EPSG:3857、EPSG:4326和EPSG:3413坐标转换误差可接受。
- 高纬点位在投影切换后保持合理位置。
- 图层范围定位不出现全球缩放或空白。
- 180度经线附近数据不产生异常长线。
- 距离和面积单位正确。
- WMS/WMTS请求使用正确CRS和范围。
- 不支持目标投影的图层显示明确提示。

## 7. 上传安全测试

- 超过5GB限制。
- 扩展名与内容不匹配。
- ZIP包含 `../` 路径。
- ZIP包含绝对路径或符号链接。
- 高压缩比解压炸弹。
- 缺少Shapefile必要组成文件。
- 无坐标系或非法几何。
- 文件名包含控制字符、超长文本和特殊字符。
- 同一内容重复上传。
- S-57批次超过5000个直接上传文件或总量超过5GB。
- S-57目录模式一次上传1001至5000个文件时应成功通过multipart解析，不得受框架默认1000文件限制影响。
- ZIP成员超过10000个、解压后总量超过20GB或含加密/异常成员。
- 目录模式混入ZIP或非三位数字扩展名文件时由接口拒绝；前端目录选择会先忽略非S-57文件。
- 上传 API 与 Worker 未共享存储时，批次必须以`S57_BATCH_SOURCE_UNAVAILABLE`失败并提示重新通过同一部署环境上传，错误中不得包含服务器绝对路径。

## 8. 性能测试

### 8.1 API

- 50并发用户执行登录后项目列表、地图配置和属性分页。
- 普通业务接口95百分位目标2秒。
- 验证数据库连接池不耗尽。

### 8.2 地图

- 典型项目10–30个图层，默认可见图层不超过合理数量。
- 缓存命中时地图首屏目标5秒。
- 单图层失败不阻塞其他图层。

### 8.3 导入

- 验证上传流式写入，不随文件大小线性增加Web进程内存。
- 验证Worker运行时API仍可响应。
- 验证大批次处理期间心跳持续更新、同一单元更新任务不并发执行、单元失败不会阻塞后续单元。
- 同一数据集并发更新只有一个任务执行。

### 8.4 属性查询

- 分页查询不执行无界全表扫描。
- 默认最大1000条限制生效。
- 空间和常用字段查询使用索引。

## 9. 安全测试

- 未授权访问和角色提升。
- JWT过期、伪造和刷新令牌重放。
- SQL注入和筛选字段注入。
- 路径穿越和任意文件读取。
- XSS属性值展示。
- CSRF刷新和退出行为。
- 敏感错误信息泄漏。
- GeoServer管理接口暴露。

## 10. 覆盖率与质量门禁

- 核心业务代码覆盖率目标不低于80%。
- 权限、S-57更新、项目发布和任务状态不得仅依赖手工测试。
- 任何阻断级或高优先级缺陷未关闭时不得验收。
- 不允许通过跳过测试或删除断言获得通过。

具体测试命令在脚手架建立后写入项目配置和 `AGENTS.md`，不得在当前无实现阶段虚构命令。

## 11. 需求验收追踪

测试用例必须标记对应的 `FR-*` 编号。至少建立：

- 需求编号。
- 自动化用例编号。
- 手工用例编号。
- 结果。
- 缺陷链接。
- 验收人和日期。

## 12. 发布验收清单

- 数据库迁移从空库执行成功。
- 管理员和普通用户关键流程通过。
- S-57基础单元、两个更新和回退通过。
- 常规和北极投影通过。
- 普通用户不能进入管理接口或下载原始海图。
- 导入失败和GeoServer失败恢复流程通过。
- AIS和气象均显示演示标识。
- 截图、PDF和导出包含必要免责声明。
- 生产Compose环境健康检查通过。
- 已知限制已记录。
