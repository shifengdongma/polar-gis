# 极地海洋环境信息平台开发计划

> 当前仓库已完成一期可运行基线及主要业务闭环。真实S-57连续更新、5GB上传、PostGIS/GeoServer发布、并发与容量指标仍必须在具备验收样本和完整外部服务的环境执行。

## 1. 计划基线

- 周期：12周。
- 团队：1名前端、1名后端/GIS开发、1名测试兼产品支持。
- 架构：Vue前端 + FastAPI单体 + 独立导入Worker。
- 开发环境：Windows可直接运行，第三方服务手动安装。
- 生产环境：Linux + Docker Compose。

计划以可验收的纵向功能切片组织，不先建设长期不可见的“大平台底座”。

## 2. 里程碑

| 里程碑 | 周期 | 结果 |
|---|---|---|
| M1 技术基线 | 第1–2周 | 脚手架、登录、数据库迁移、GeoServer和S-57验证 |
| M2 数据闭环 | 第3–5周 | 上传、任务、Worker、基础数据导入和发布 |
| M3 S-57闭环 | 第6–7周 | 基础单元、增量更新、样式和版本回退 |
| M4 用户地图 | 第8–9周 | 项目地图、投影、图层树、查询和导出 |
| M5 完整一期 | 第10–12周 | 管理端、演示数据、测试、性能和部署验收 |

## 3. 周计划

### 第1周：工程与标准验证

后端/GIS：

- 建立FastAPI、SQLAlchemy、Alembic和配置框架。
- 验证PostGIS、GeoServer REST和GDAL版本兼容性。
- 使用真实脱敏S-57样本完成GDAL解析PoC。
- 确认核心S-57对象及初始SLD映射范围。

前端：

- 建立Vue 3、TypeScript、Vite、Element Plus和Pinia。
- 建立视觉变量、全局布局和路由骨架。
- 完成OpenLayers普通投影和EPSG:3413显示PoC。

测试/产品：

- 建立需求追踪矩阵。
- 整理S-57验收样本和预期对象。
- 确认浏览器与测试环境。

退出条件：真实S-57样本可解析，GeoServer可发布测试图层，前端可显示普通和北极投影。

### 第2周：认证、用户和项目骨架

- 实现用户、刷新令牌、Argon2和JWT。
- 实现两个角色和后端权限依赖。
- 完成登录、退出和管理员用户页面。
- 建立项目表、项目列表、创建和编辑接口。
- 建立统一错误、请求ID、健康检查和审计基础。
- 编写认证和权限测试。

退出条件：管理员可创建普通用户，两个角色访问边界通过自动化测试。

### 第3周：数据目录和文件上传

- 实现统一本地存储接口。
- 实现5GB流式上传和安全校验。
- 建立数据集、版本、文件和任务表。
- 完成数据目录、上传和数据集详情页面。
- 建立任务轮询和状态组件。
- 覆盖恶意压缩包、错误格式和超限文件测试。

### 第4周：Worker与通用矢量导入

- 实现PostgreSQL任务领取和Worker主循环。
- 实现GeoJSON和Shapefile导入。
- 生成候选空间表、索引和图层元数据。
- 集成GeoServer工作区、存储和图层发布。
- 完成任务日志和失败重试。
- 管理端展示导入阶段和错误。

### 第5周：栅格、样式和项目图层

- 实现GeoTIFF/COG校验和发布。
- 实现SLD上传、校验和GeoServer发布。
- 实现图层目录和数据集级项目配置；保存时自动展开当前版本内部图层，避免在管理界面暴露S-57对象分类。
- 完成图层分组、顺序、默认显隐和透明度编辑。
- 建立项目发布前校验。

退出条件：GeoJSON、Shapefile和GeoTIFF均能从上传走到项目发布。

### 第6周：S-57基础单元

- 实现 `.000` 单元识别、元数据提取和导入。
- 建立S-57对象类别映射。
- 生成关键点、线、面图层和空间索引。
- 完成核心S-52近似SLD样式第一版。
- 管理端展示单元、版次、更新号、比例尺和范围。
- 编写基础单元、错误文件和重复导入测试。

### 第7周：S-57增量更新和回退

- 实现 `.001`、`.002` 连续更新校验。
- 实现候选版本、原子切换和失败清理。
- 实现版本历史和上一版本回退。
- 覆盖缺失更新、错误单元、版次冲突和并发更新测试。
- 完善S-57图例和免责声明。
- 实现ZIP/本地目录批量导入，按单元自动归组`.000`和连续更新并分别创建数据集、版本及任务。
- 已有有效S-57数据集自动跳过已应用更新并追加连续新更新，避免重复导入同一单元。
- 实现批次和单元进度、部分失败汇总、失败详情以及分页轮询界面。

退出条件：至少一套样本完成基础单元、两个增量更新及回退演示。

### 第8周：地图工作台

- 实现项目地图配置接口。
- 完成地图工作台布局和图层树。
- 实现常规地图与北极投影切换。
- 实现离线WMTS/XYZ底图配置。
- 实现显隐、透明度、临时排序、图例、元数据和定位到图层。
- 实现坐标显示、距离和面积测量。

### 第9周：查询、属性表、导出和打印

- 实现要素识别和允许字段控制。
- 实现属性表服务端分页和筛选。
- 实现地图与表格双向定位。
- 实现CSV和GeoJSON受控导出及审计。
- 实现截图和PDF打印。
- 优化图层加载错误隔离。

退出条件：普通用户可完成浏览、查询、测量、打印和筛选结果导出。

### 第10周：管理端完整化和演示适配器

- 完成项目发布、撤回、归档和软删除。
- 完成数据集引用检查、单项及批量软删除入口和管理员单项、批量物理清理预览/确认流程。
- 完成图层停用、样式管理、底图配置和审计日志。
- 实现AIS演示数据适配器和地图展示。
- 实现气象选点演示接口和图表。
- 全面增加“演示数据”和“非认证航海显示”提示。

### 第11周：质量、性能和安全

- 补齐单元、集成和端到端测试。
- 达到核心业务代码80%覆盖目标。
- 执行50并发用户基线测试。
- 优化PostGIS索引、查询分页和GeoWebCache。
- 执行上传安全、权限绕过、路径穿越和敏感信息检查。
- 处理1366×768和1920×1080界面问题。

### 第12周：验收和交付

- 部署Linux Docker Compose验收环境。
- 执行完整需求追踪和回归测试。
- 完成管理员、普通用户和故障恢复演示。
- 修复阻断级和高优先级问题。
- 完善安装、部署、运维和已知限制文档。
- 形成一期验收报告和二期建议列表。

### 后端/GIS开发

### 测试兼产品支持

- 需求追踪、测试用例和验收数据。
- 手工探索测试和端到端自动化支持。
- UI验收、文案和错误场景核对。

## 5. 关键依赖

```text
S-57/GDAL PoC
  → 数据模型
  → Worker和导入
  → GeoServer发布
  → 项目图层
  → 地图展示
  → 查询与导出

认证与角色
  → 管理接口
  → 普通用户验收
```

S-57 PoC是第一周强制闸门。若真实样本不能稳定解析，应先调整范围，不得在未知格式问题上继续堆叠页面功能。

## 6. 优先级

### P0：一期必须完成

- 登录、两个角色和权限。
- 项目、数据集、图层和发布。
- S-57基础单元和连续更新。
- 常规与北极投影。
- 图层树、查询、测量和打印。
- 受控导出。
- Worker、任务状态和错误日志。
- S-57 ZIP/目录批量导入、单元内串行更新、批次进度和失败项。

### P1：一期应完成

- GeoTIFF、Shapefile和GeoJSON。
- 离线底图配置。
- AIS和气象演示适配器。
- 审计日志和基础性能优化。

### P2：时间允许优化

- 更丰富的S-57对象样式。
- 其他管理端批量操作。
- 更多打印布局。
- 更细致的图层元数据展示。

P2不得挤占P0缺陷修复时间。

## 7. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| S-57样本差异大 | 导入延期 | 第一周真实样本PoC，保留原始属性和失败日志 |
| S-52表达范围过大 | 样式延期 | 固定关键对象清单，明确非认证范围 |
| 极区和180度经线问题 | 地图异常 | 专项投影和跨日期变更线测试 |
| GeoServer发布不稳定 | 图层不可用 | 幂等发布、重试和发布状态分离 |
| 5GB上传和导入耗时 | 用户误判失败 | 流式上传、异步任务、进度和超时配置 |
| 3人团队并行受限 | 集成延期 | 按纵向切片开发，每周保持可运行主干 |
| 无自动备份 | 数据丢失 | 明确风险；至少保留可重复导入的原始样本和配置模板 |

## 8. 变更控制

以下变化必须重新评估周期：

- 增加正式实时AIS或气象数据源。
- 增加自动航线规划或油污漂移。
- 要求ECDIS/S-52认证。
- 增加手机端、三维地图或多租户。
- 增加生产级S-101/S-102。
- 显著提高并发、图层数或文件大小。

## 9. 完成定义

每个需求完成必须满足：

- 前后端行为符合需求编号。
- 权限在后端验证。
- 数据库迁移可从空库执行。
- 错误和边界情况可见且可恢复。
- 自动化测试通过。
- 相关文档更新。
- 不包含真实凭据和生产数据。
