## 幻灯片 3：目前进展 — 数据管理能力

### 文字内容

**S-57 批量导入**：
- 支持 `.000` 基座 + `.001`/`.002`/`.003` 顺序更新链自动识别与校验
- 单次最多上传 5,000 个文件，ThreadPoolExecutor 8 线程并行处理
- 支持暂停/恢复/取消控制，实时进度监控
- 导入性能优化 30-120 倍：从单层多次 ogr2ogr → 单 Cell 一次 ogr2ogr + ALTER TABLE 迁移

**全球海图底图一键导入**：
- 预检（文件扫描、更新链校验、数据状态对比）→ 分批导入 → 图层组发布 → EPSG:3857/3413 WMTS 注册 → 缓存预热，全流程自动化
- 当前内置 `global_overview_v1` 底图配置（18 个 Cell、29 个文件）

**数据集版本管理**：
- 父子版本链，支持 S-57 顺序更新追加（`.001` → `.002` → ...）
- 支持版本回退（回滚到上一版本，自动切换项目图层引用）
- 软删除 + 级联清理（GeoServer 图层 + PostGIS geo schema 表 + 文件资产）

**多格式支持**：S-57 电子海图 / Shapefile 矢量 / GeoJSON / GeoTIFF 栅格

## 幻灯片 4：目前进展 — 地图可视化能力

### 文字内容

**三投影支持**：
- EPSG:3413 Arctic Stereographic（北极极地投影，主要工作投影）
- EPSG:3857 Web Mercator（标准 Web 地图）
- EPSG:4326 WGS84（数据存储与全球参考）

**智能渲染调度器**（自主研发核心模块）：
- **3 种渲染模式**：standard（全量独立 WMS）/ smart（视口裁剪 + 比例尺过滤 + warming 预算）/ overview（全球概览 WMTS）
- **7 状态图层生命周期**：selected → attached → warming → active → suspended → failed → manuallyForced
- **视口裁剪**：基于 `s57.extent` 真实数据范围，仅渲染当前视口内图层
- **比例尺过滤**：SOUNDG 仅在 ≥1:25,000 渲染，LIGHTS 仅在 ≥1:50,000，DEPCNT 仅在 ≥1:500,000
- **Warming 预算**：同时最多 10 层加载首块瓦片，活动预算 30 层，内存上限 60 层，LRU 超限驱逐
- **防抖优化**：150ms moveend 防抖，避免拖拽时频繁重算

**组合图层渲染（Bundle）**：
- 智能模式下 20~30 个独立 TileWMS 压缩为 3~6 个语义组合 TileWMS
- 5 个语义分组：面域填充(z:10) / 线状结构(z:20) / 危险物与水深(z:30) / 助航标志(z:50) / 其他可选(z:100)
- 逗号分隔 LAYERS/STYLES 参数，单次 WMS 请求渲染多层

**GWC 瓦片缓存全链路**：
- EPSG:3413 GridSet 创建 + 图层自动启用三级 GridSet（3857/4326/3413）
- cacheable 图层走 `/geoserver/gwc/service/wms`（命中直接返回缓存 PNG）
- Nginx proxy_cache 10GB，1 小时缓存，HTTP/2 多路复用
- 已有图层一键幂等回填（`POST /admin/gwc/backfill`）

**其他地图功能**：点击识别 (GetFeatureInfo) / 属性表分页查询导出 / 距离面积测量 / 底图切换 / 天气查询

## 幻灯片 7：系统连接与部署方式

### 文字内容

**系统架构（5 层）**：

```
用户浏览器 (HTTPS)
    │
    ▼
┌──────────────────────────────────────┐
│  Nginx (web)                         │
│  · 前端静态文件 (Vue 3 SPA)           │
│  · 反向代理 /api → backend           │
│  · 反向代理 /geoserver → GeoServer   │
│  · HTTP/2 多路复用                    │
│  · WMS 瓦片缓存 (proxy_cache 10GB)   │
│  · 静态资源 immutable 缓存 (1年)     │
└──────────────────────────────────────┘
    │                   │
    ▼                   ▼
┌──────────────┐  ┌──────────────────┐
│  backend     │  │  geoserver       │
│  FastAPI     │  │  GeoServer 2.25  │
│  :8000       │  │  :8080           │
│              │  │  + GeoWebCache   │
│  · JWT 认证  │  │  · WMS/WMTS 服务 │
│  · 业务逻辑  │  │  · GWC 瓦片缓存  │
│  · GDAL 调用 │  │  · SLD 样式渲染  │
└──────┬───────┘  └──────────────────┘
       │                   │
       ▼                   │
┌──────────────┐           │
│  worker      │           │
│  (后台导入)   │           │
│  · 轮询任务   │           │
│  · ogr2ogr   │           │
│  · 并行处理   │           │
└──────┬───────┘           │
       │                   │
       ▼                   ▼
┌──────────────────────────────────────┐
│  PostgreSQL 16 + PostGIS 3.4         │
│  :5432                               │
│  · 16 张业务表 (default schema)      │
│  · geo schema (导入的空间数据表)      │
│  · PostGIS 空间索引 (GIST)           │
└──────────────────────────────────────┘
```

**部署方式**：

| 环境 | 方式 | 说明 |
|------|------|------|
| **开发环境** | 本地手动启动 | PostgreSQL + GeoServer 连接内网虚拟机 `192.168.92.129`，FastAPI + Vite 本机运行 |
| **生产环境** | Docker Compose | 单机 5 容器编排，`docker compose up -d --build` 一键启动 |
| **容器镜像** | 自构建 | backend/worker 共享 `polar-gis-backend:latest`，web 使用 `polar-gis-frontend:latest` |

**关键配置**：
- GeoServer JVM：2G 初始 / 4G 最大，G1GC，字符串去重
- 文件上传限制：5 GB（Nginx `client_max_body_size`）
- 共享存储卷：`shared-storage` 挂载到 backend / worker / geoserver（只读）
- S-57 底图数据卷：`./data/s57-basemaps:/data/s57-basemaps:ro`

**网络**：
- `public` 网络：web + geoserver + postgres（对外暴露）
- `internal` 网络：backend + worker + postgres + geoserver + web（服务间通信）

## 幻灯片 8：下一步计划 — 前端图层加载速度与渲染流畅度优化

### 文字内容

**当前状态**：
- 批量加载 160 层海图已实现基本可用（GWC 缓存 + 智能调度 + Bundle 压缩）
- 后端测试 168 通过，前端测试 77 通过，vue-tsc 零错误
- 已知优化空间：首屏加载时间、Bundle 模式下的瓦片调度、大量图层切换时的响应速度

**下一步优化方向**：

| 优先级 | 方向 | 具体措施 | 预期效果 |
|--------|------|----------|----------|
| P0 | **首屏加载加速** | ① 按视口优先级分批次 attach（先可视区域，后周边） ② 首屏瓦片预加载（低缩放级别预生成） ③ 图层树虚拟滚动（160 层渲染性能） | 首屏可交互时间缩短 50%+ |
| P0 | **Bundle 瓦片调度优化** | ① Bundle 级别 warming 队列（替代逐层 warming） ② Bundle 内图层差异化退避（高成本层延迟加载） ③ 跨 Bundle 优先级排序（视口中心优先） | Bundle 模式首帧时间缩短 40% |
| P1 | **图层切换响应优化** | ① 开关操作改为乐观更新（先改 UI，后确认瓦片） ② 批量开关合并调度（debounce 200ms） ③ 取消进行中的无效瓦片请求（AbortController） | 开关 160 层响应从秒级 → 百毫秒级 |
| P1 | **内存与 GPU 优化** | ① 离屏 Canvas 预合成（同 Bucket 瓦片合并渲染） ② TileLayer 对象池复用 ③ LRU 驱逐策略精细化（按渲染成本 + 最近使用时间加权） | 内存占用降低 30%，GC 停顿减少 |
| P2 | **缓存策略增强** | ① Service Worker 缓存瓦片（离线可用） ② IndexedDB 持久化图层元数据（减少首屏 API 请求） ③ 预取相邻缩放级别瓦片 | 二次打开秒开，离线可浏览已缓存区域 |
| P2 | **网络层优化** | ① 瓦片请求优先级（视口中心 HIGH → 边缘 LOW） ② HTTP/3 (QUIC) 升级 ③ Brotli 压缩 WMS 响应 | 弱网环境体验改善 |

**技术路线图**：

```
2026年8月 (当前)          2026年9月                 2026年10月
─────────────────────────────────────────────────────────────
✅ GWC 3413 全链路        🔲 首屏加速 + 虚拟滚动      🔲 SW 离线缓存
✅ 智能调度器 3 模式       🔲 Bundle 瓦片调度优化       🔲 HTTP/3 + Brotli
✅ Bundle 组合渲染         🔲 图层切换响应优化          🔲 GPU 预合成
✅ SLD 比例尺 + bbox      🔲 内存/GPU 优化             🔲 预取策略
```
