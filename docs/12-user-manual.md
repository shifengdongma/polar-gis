## 1. 系统概述

### 1.1 平台简介

**Polar-GIS（极地海洋环境信息平台）** 是一个面向极地和高纬度海洋环境数据的全栈 WebGIS 平台。系统一期正式支持 S-57 电子海图（基础单元和连续更新），提供项目组织、数据管理、图层发布、空间查询、测量工具、地图打印和受控导出等完整功能。

### 1.2 核心特性

| 特性 | 说明 |
|------|------|
| 🌊 **S-57 海图支持** | 完整支持 IHO S-57 标准电子海图的导入、更新链管理、自动样式渲染 |
| 🗺️ **北极投影** | 内置 EPSG:3413 北极立体投影，专为极地高纬度区域优化 |
| 📊 **空间查询** | 支持要素识别、属性查询、空间过滤、数据导出（CSV/GeoJSON） |
| 🎨 **自动样式** | 10 种内置 S-57 制图样式（岸线、水深、助航标志等），支持自定义 SLD |
| 📏 **测量工具** | 距离测量、面积测量、坐标显示 |
| 📸 **地图输出** | 截图保存、打印输出 |
| 🔄 **版本管理** | 数据集版本链、增量更新、版本回滚 |
| 👥 **权限控制** | 系统管理员 / 普通用户 双角色，细粒度操作权限 |

### 1.3 技术架构

```
┌──────────────────────────────────────────────────────┐
│                    用户浏览器                          │
│         Vue 3 + OpenLayers + Element Plus             │
└──────────────┬───────────────────────────────────────┘
               │ HTTP/HTTPS
┌──────────────▼───────────────────────────────────────┐
│                 Nginx (反向代理)                       │
│         静态文件服务 / API代理 / GeoServer代理          │
└──────┬──────────────┬────────────────┬───────────────┘
       │              │                │
┌──────▼──────┐ ┌─────▼─────┐  ┌──────▼──────┐
│  Backend    │ │  Worker   │  │  GeoServer  │
│  FastAPI    │ │  轮询处理  │  │  地图服务    │
│  API 服务   │ │  导入任务  │  │  WMS/WFS    │
└──────┬──────┘ └─────┬─────┘  └──────┬──────┘
       │              │                │
       └──────────────┼────────────────┘
                      │
              ┌───────▼───────┐
              │  PostgreSQL   │
              │  + PostGIS    │
              │  + 业务数据    │
              └───────────────┘
```

- **后端**：Python 3.12+ / FastAPI + SQLAlchemy + PostgreSQL/PostGIS + GDAL
- **前端**：Vue 3 + Vite + TypeScript + Element Plus + OpenLayers + ECharts + Pinia
- **部署**：Docker Compose（5 个服务：postgres, geoserver, backend, worker, web/nginx）
- **支持投影**：EPSG:3857（Web墨卡托）、EPSG:4326（WGS84）、EPSG:3413（北极立体投影）

### 1.4 用户角色

| 角色 | 权限范围 |
|------|---------|
| **系统管理员** (`system_admin`) | 完全控制：用户管理、数据导入、项目配置、图层发布、样式管理、系统监控 |
| **普通用户** (`user`) | 查看已发布项目、浏览地图、空间查询、要素导出、测量工具 |

## 2. 安装与部署

### 2.1 环境要求

#### 开发环境

| 组件 | 版本要求 |
|------|---------|
| Python | 3.12+ |
| Node.js | 20+ |
| PostgreSQL | 16 + PostGIS 3.4 |
| GeoServer | 2.25.x |
| GDAL | 3.x（需 ogrinfo, ogr2ogr, gdalinfo） |
| Java | 17+（GeoServer 运行需要） |

#### 生产环境（Docker）

- Docker Engine 24+
- Docker Compose v2
- 建议内存：8GB+
- 建议磁盘：50GB+（含数据存储空间）

### 2.2 快速部署（Docker Compose）

**步骤 1：获取代码**

```bash
git clone https://github.com/shifengdongma/polar-gis.git
cd polar-gis/deploy
```

**步骤 2：配置环境变量**

```bash
cp .env.example .env
```

编辑 `.env` 文件，修改以下关键配置：

```env
# 数据库配置
POSTGRES_DB=polar_gis
POSTGRES_USER=polar_user
POSTGRES_PASSWORD=<设置强密码>

# JWT 签名密钥（请使用随机字符串）
APP_SECRET_KEY=<生成随机密钥>

# 初始管理员账号（首次启动时自动创建）
INITIAL_ADMIN_USERNAME=admin
INITIAL_ADMIN_PASSWORD=<设置管理员密码>

# GeoServer 管理员凭据
GEOSERVER_ADMIN_USER=admin
GEOSERVER_ADMIN_PASSWORD=<设置GeoServer密码>

# 对外访问端口
PUBLIC_PORT=8088
```

**步骤 3：启动服务**

```bash
docker compose up -d --build
```

首次构建需要 5-10 分钟（下载镜像、安装依赖、构建前端）。

**步骤 4：验证部署**

访问以下地址验证各服务状态：

| 服务 | 地址 | 说明 |
|------|------|------|
| 前端应用 | `http://localhost:8088` | 用户界面入口 |
| API 健康检查 | `http://localhost:8088/api/v1/health/live` | 返回 `{"status":"ok"}` |
| API 就绪检查 | `http://localhost:8088/api/v1/health/ready` | 数据库+存储检查 |
| GeoServer | `http://localhost:8080/geoserver/` | GeoServer 管理界面 |
| API 文档 (Swagger) | `http://localhost:8088/api/docs` | 交互式 API 文档 |

### 2.3 服务组成

| 服务名称 | 功能 | 内部端口 | 对外端口 |
|---------|------|---------|---------|
| `postgres` | PostgreSQL 16 + PostGIS 3.4 数据库 | 5432 | 5432 |
| `geoserver` | GeoServer 2.25.3 地图服务器 | 8080 | 8080 |
| `backend` | FastAPI 后端 API 服务 | 8000 | —（仅内网） |
| `worker` | 后台导入任务处理器 | — | —（仅内网） |
| `web` | Nginx + 前端静态资源 | 80 | `${PUBLIC_PORT}`（默认8088） |

### 2.4 常用运维命令

```bash
# 查看所有服务状态
docker compose ps

# 查看服务日志
docker compose logs -f backend    # 后端日志
docker compose logs -f worker     # 导入任务日志
docker compose logs -f web        # Web 访问日志

# 重启单个服务
docker compose restart backend

# 停止所有服务
docker compose down

# 停止并清理数据卷（⚠️ 危险操作，会删除所有数据）
docker compose down -v
```

## 3. 快速入门

### 3.1 首次登录

1. 打开浏览器访问 `http://localhost:8088`
2. 使用初始管理员账号登录（用户名和密码为 `.env` 中配置的 `INITIAL_ADMIN_USERNAME` / `INITIAL_ADMIN_PASSWORD`）
3. 首次登录后，建议立即修改管理员密码

### 3.2 典型工作流程

```
管理员操作流程：
  上传数据 → 创建数据集 → 等待导入完成 → 配置样式 → 创建项目 → 分配图层 → 发布项目

普通用户操作流程：
  登录 → 浏览项目 → 打开地图 → 查看图层 → 空间查询 → 导出数据
```

### 3.3 一分钟体验

1. **登录系统** → 进入项目门户
2. **点击已发布项目** → 进入地图工作台
3. **左侧面板** → 切换图层可见性
4. **点击地图** → 查看要素属性
5. **右上角工具栏** → 使用测量/截图功能
6. **左上角按钮** → 切换北极/常规投影

#### 4.3.2 图层面板（左侧）

**底图选择器**：下拉菜单选择底图，选项会根据当前投影自动过滤（支持 XYZ 和 WMTS 类型）。

**图层搜索**：输入关键词快速定位图层，支持按数据集名称、代码、分组名、图层名称搜索。

**图层树结构**：
```
📁 分组名称 (N个图层)
  └─ 📂 数据集名称 [代码] (N层)
       ├─ ☑ 图层名称                                    [⚙]
       ├─ ☐ 图层名称                                    [⚙]
       └─ ...
```

**图层控制**（点击图层右侧 ⚙ 按钮）：
- **透明度调节**：滑块 0-100%，步长 5%
- **缩放到图层范围**
- **查看图例与元数据**
- **打开属性表**

**快速切换**：
- 点击图层名称左侧的开关直接切换可见性

#### S-57 图层批量加载（新增功能）

> **注意**："批量加载"是指在地图工作台中批量创建和显示 WMS 图层，与"批量导入"（将 S-57 文件导入到数据库）是两个完全不同的功能。

当项目包含 S-57 海图数据集时，图层面板的搜索框下方会显示批量操作工具栏。

**选择数据集**：
- 每个 S-57 数据集行左侧有复选框，无需展开即可勾选。
- "全选当前结果"仅选中当前搜索过滤后的数据集。
- "清空选择"只取消复选框，不会卸载已加载的图层。

**批量加载**：
1. 勾选一个或多个 S-57 数据集。
2. 点击"批量加载"下拉菜单，选择加载档案：
   - **加载核心海图层**：仅加载 12 种核心海图对象（水深、岸线、危险物等）。
   - **加载推荐海图层**：核心海图层 + 航行推荐层（灯标、浮标、分道通航、限制区等，共 36 种）。
   - **加载全部可显示图层**：所有有几何且可渲染的空间图层（含未配置样式的图层和可选专题图层）。
3. 系统自动解析、筛选和排序后，分批创建 WMS 图层。
4. 进度区域显示处理进度、成功数、失败数和跳过数。

**限制**：
- 候选图层 > 40 个时需二次确认。
- 候选图层 > 120 个时阻止执行，提示缩小选择范围。
- 每批创建 5 个图层，批次间间隔 200ms。

**取消与卸载**：
- 点击"取消剩余"停止尚未创建的图层；已创建的图层保留。
- "卸载本次加载"仅清理最近一次批量加载创建的图层。
- "卸载所选数据集图层"按数据集复选框状态卸载。
- "卸载当前搜索结果图层"仅处理当前搜索过滤结果。
- "卸载全部海图图层"仅卸载业务海图 WMS，不影响底图、AIS、气象和测量图层。

**自动跳过**：
- 非空间层（DSID、C_AGGR）永远不创建 WMS。
- 未发布或不可用的图层。
- 元数据/质量层（M_COVR 等）默认不加载。
- 核心/推荐模式下，未映射样式的图层不自动加载。

#### 4.3.3 地图工具（右侧工具栏）

| 工具 | 图标 | 功能说明 |
|------|------|---------|
| 🔍 **要素识别** | 📍 | 点击地图上的要素查看属性信息。激活后光标变为十字准星，点击地图任意位置，系统在容差范围内搜索要素并显示属性 |
| 🌡️ **气象查询** | 📊 | （演示模式）点击地图任意位置查看 72 小时气象预报（温度、风速、浪高） |
| 📏 **距离测量** | ↔️ | 在地图上绘制线段，自动计算并显示总距离。支持多段连续测量 |
| ⬛ **面积测量** | ⏹️ | 在地图上绘制多边形，自动计算并显示面积 |
| 📸 **地图截图** | 📷 | 将当前地图画布保存为 PNG 图片并下载 |
| 🖨️ **地图打印** | 🖨️ | 调用浏览器打印功能输出当前地图 |

**注意**：要素识别和气象查询为互斥模式，同一时间只能激活一个。

#### 4.3.4 投影切换

顶部中央的投影切换按钮支持两种投影模式：

| 投影 | EPSG 代码 | 适用场景 |
|------|-----------|---------|
| 🌍 **常规地图** | EPSG:3857 | 全球范围、中低纬度地区 |
| 🧊 **北极投影** | EPSG:3413 | 极地高纬度区域（北纬60°以上） |

切换投影时，底图选择器会自动过滤兼容的底图。

#### 4.3.5 属性表与数据导出

对于启用了"可查询"和"可导出"的图层，可以打开属性表：

1. 点击图层的 ⚙ 按钮 → "查看属性表"
2. 属性表以抽屉面板从右侧滑出（占屏幕 55%）
3. 支持字段过滤搜索
4. 支持分页浏览
5. 可导出为 **CSV** 或 **GeoJSON** 格式

#### 4.3.6 环境叠加层

图层面板底部提供"环境叠加层"下拉菜单：

- **AIS 船舶演示** 🚢：在地图上显示模拟的 AIS 船舶位置（演示数据，非真实数据）
- 所有演示数据均标注"演示"标记

|------|------|

## 6. 数据格式支持

### 6.1 支持的数据类型

| 数据类型 | 格式 | 扩展名 | 导入方式 |
|---------|------|--------|---------|
| 🌊 **S-57 海图** | IHO S-57 | `.000`（基础）/ `.001`-`.999`（更新） | 单文件 / 批量导入 |
| 🗺️ **矢量数据** | GeoJSON | `.geojson` `.json` | 文件上传 |
| 🗺️ **矢量数据** | Shapefile | `.zip`（含 .shp/.shx/.dbf） | 文件上传 |
| 🏔️ **栅格数据** | GeoTIFF | `.tif` `.tiff` | 文件上传 |

### 6.2 S-57 数据特别说明

**什么是 S-57？**
S-57 是国际海道测量组织（IHO）制定的数字海道测量数据传输标准，是全球电子海图（ENC）的标准格式。

**本平台的 S-57 支持**：
- ✅ 自动识别 S-57 文件（通过扩展名和 GDAL 驱动）
- ✅ 自动提取海图元数据（单元名称、更新编号、图层列表）
- ✅ 自动将 23 种 S-57 对象类映射到 10 种制图样式
- ✅ 支持增量更新链（`.000` 基础 → `.001` → `.002` ...）
- ✅ 支持版本回滚
- ✅ 支持批量导入（ZIP/目录）
- ❌ 不是经认证的 ECDIS（不可替代法定海图设备）

**S-57 更新链规则**：
- 基础文件扩展名为 `.000`，更新文件为 `.001`、`.002` ... 依次递增
- 更新链必须连续（不能跳过编号）
- 同一单元的所有文件扩展名之前的文件名（Cell Name）必须一致
- 示例：`US5AK1ZM.000` → `US5AK1ZM.001` → `US5AK1ZM.002` ✅

### 6.3 文件大小限制

- 单文件最大：**5 GB**
- ZIP 解压后最大：**20 GB**
- ZIP 最大条目数：**10,000**
- 查询导出最大行数：**1,000**（可配置）

| `POST` | `/api/v1/layers/{id}/exports` | 导出数据（CSV / GeoJSON） |

#### 要素查询示例

```bash
curl -X POST http://localhost:8088/api/v1/layers/{layer_id}/features/search \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "page": 1,
    "pageSize": 20,
    "filters": [
      {"field": "DEPTH", "operator": "gt", "value": "50"}
    ],
    "bbox": [-180, 60, 180, 90],
    "bboxCrs": "EPSG:4326"
  }'
```

**支持的过滤操作符**：`eq`（等于）、`ne`（不等于）、`gt`（大于）、`gte`（大于等于）、`lt`（小于）、`lte`（小于等于）、`contains`（模糊包含）、`in`（列表匹配）

#### 导出示例

```bash
curl -X POST http://localhost:8088/api/v1/layers/{layer_id}/exports \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "format": "geojson",
    "bbox": [-180, 60, 180, 90],
    "fields": ["DEPTH", "DEPCNT", "QUASOU"]
  }' \
  -o export.geojson
```

## 8. 常见问题

### 8.1 登录问题

**Q: 登录时提示"账号已锁定"？**
> 连续 5 次密码错误会触发 15 分钟锁定。请等待 15 分钟后重试，或联系其他管理员重置密码。

**Q: 登录后很快提示需要重新登录？**
> 访问令牌有效期为 30 分钟，但浏览器会自动通过刷新令牌续期。如果长时间未操作，刷新令牌也可能过期（7天），需要重新登录。

**Q: 浏览器刷新后需要重新登录？**
> 通常不需要，系统会自动尝试恢复会话。如果 Cookie 被清除或过期，则需要重新登录。

### 8.2 数据导入问题

**Q: 上传 S-57 文件后长时间无反应？**
> 导入任务由后台 Worker 异步处理。请前往"导入任务"页面查看任务状态和进度。Worker 默认每 2 秒轮询一次新任务。

**Q: S-57 更新导入失败，提示"更新间隔"？**
> 增量更新必须严格连续。例如已有 `.000` 和 `.001`，下次只能上传 `.002`。如上传 `.003` 会因缺少 `.002` 而失败。

**Q: Shapefile 上传后导入失败？**
> 请确认 ZIP 包中同时包含 `.shp`、`.shx`、`.dbf` 三个必需文件。PRJ（投影文件）为可选但建议包含。

**Q: 支持哪些字符编码的属性数据？**
> 建议使用 UTF-8 编码。GDAL 导入时会处理编码转换。

### 8.3 地图显示问题

**Q: 切换到北极投影后图层消失？**
> 并非所有数据都支持 EPSG:3413 投影。GeoServer 会尝试动态重投影，但数据源必须在合理的地理范围内（高纬度区域）。

**Q: 地图上无法点击要素查看属性？**
> 请确认：
> 1. 图层可见性已打开
> 2. 该图层已启用"可查询"属性（管理员在图层管理中设置）
> 3. 已激活要素识别模式（右侧工具栏 📍 按钮）
> 4. 点击位置在图层数据范围内

**Q: 属性表中文字段显示为乱码？**
> 这通常与数据源的编码设置有关。请检查 GDAL 导入时的编码选项或联系管理员。

### 8.4 项目管理问题

**Q: 项目无法发布？**
> 项目发布需要至少关联一个状态为"可用"的图层。请先在"配置图层"中添加数据集。

**Q: 数据集无法删除？**
> 如果数据集被任何项目引用，系统会阻止删除并列出引用项目。请先在对应项目中移除该数据集。

**Q: 如何修改已发布项目的图层配置？**
> 项目发布后仍然可以修改图层配置，但建议先取消发布、修改后再重新发布，以确保用户看到的是一致的配置。

### 8.5 性能问题

**Q: 地图加载很慢？**
> 可能原因：
> - 图层数据量过大，建议在 GeoServer 中配置缓存
> - 同时开启了太多图层，建议关闭不需要的图层
> - 网络带宽不足，检查 GeoServer 和数据库连接

**Q: 导入大型 S-57 文件时系统变慢？**
> 大型数据集导入会消耗较多系统资源（GDAL 处理、PostGIS 写入、GeoServer 发布）。建议在系统负载低时进行大批量导入，避免高峰时段。

### 8.6 安全与合规

**Q: 本平台可以替代船用 ECDIS 吗？**
> **不可以！** 本平台是非认证的地理信息展示系统，不满足 IHO 电子海图显示标准，不能替代法定的 ECDIS 设备或官方电子海图系统。所有航海决策必须基于经认证的航海设备和官方海图数据。

**Q: 演示数据中的 AIS 和气象信息是否可靠？**
> **不可靠！** AIS 船舶位置和气象预报均为算法生成的模拟数据，仅用于功能演示目的，不具备任何实际参考价值。请勿将其用于航行决策。
