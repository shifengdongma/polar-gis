# 六、功能边界

“一键导入全球海图底图”包括：

1. 扫描配置的数据包目录或上传的ZIP。
2. 按内置profile选择29个目标文件。
3. 执行完整预检。
4. 创建现有S-57批量导入任务。
5. 等待18个Cell完成导入。
6. 使用成功Cell的当前有效版本生成GeoServer概览图层组。
7. 配置GeoWebCache。
8. 自动登记为系统WMTS底图。
9. 返回完整结果。

不包括：

- 删除已有数据集。
- 覆盖失败前仍可用的底图。
- 自动把所有普通项目改为使用新底图。
- 自动打开数百个业务WMS图层。
- 将底图聚合层用于要素查询。
- 宣称当前数据包全球无缝覆盖。
- 实现完整认证ECDIS或完整S-52制图表达。

# 八、预检服务

新增：

```
backend/app/services/s57_basemap.py
```

主要职责：

- 读取profile。
- 扫描数据源。
- 验证文件名。
- 按Cell归组。
- 读取DSID/DSPM元数据。
- 验证用途等级。
- 验证更新链。
- 对比数据库已有数据集和当前更新号。
- 计算将新增、更新、跳过和失败的Cell。
- 计算文件数量、文件总大小和磁盘空间估算。
- 汇总覆盖范围。
- 生成稳定manifest hash。

建议数据结构：

```python
@dataclass(frozen=True)
class BasemapProfile:
    code: str
    name: str
    usage_band: int
    load_profile: str
    expected_cells: Mapping[str, int]
    description: str
@dataclass(frozen=True)
class BasemapPreflightCell:
    cell_name: str
    expected_max_update: int
    discovered_updates: tuple[int, ...]
    edition_number: str | None
    usage_band: int | None
    compilation_scale: int | None
    extent: tuple[float, float, float, float] | None
    database_current_update: int | None
    action: str
    errors: tuple[str, ...]
```

`action`：

- `create`
- `append_updates`
- `skip_current`
- `blocked`

预检要求：

1. profile中18个Cell必须全部检查。
2. 发现`.000`缺失时标记blocked。
3. 发现中间更新缺失时标记blocked。
4. 数据库已有相同或更高更新号时标记skip_current。
5. 数据库已有较低连续更新号时只追加缺失更新。
6. 数据库历史源文件缺失时，必须确认本次数据包包含重建所需的完整链。
7. manifest hash由profile代码、文件名、文件大小和SHA-256共同计算。
8. 相同manifest重复执行时必须具有幂等性。
9. 预检不写入业务数据。
10. 预检不得调用ogr2ogr进行正式导入。

覆盖检查：

1. 读取各基础文件的M_COVR或数据集范围。
2. 计算所有Cell范围并集。
3. 返回整体WGS84 BBOX。
4. 返回覆盖经纬度区间。
5. 返回`coverageVerified`。
6. 仅凭文件名不能把`coverageVerified`设为true。
7. 不实现复杂全球无缝拓扑验算也可以，但必须返回明确提示：
   `当前数据包覆盖范围已计算，但未验证全球无缝覆盖。`

# 十一、Worker后处理

不得让Web请求等待18个Cell导入完成。

Worker流程：

```text
创建basemap批次
  → 复用现有S-57批量导入
  → 每个Cell正常创建/更新dataset
  → 批次导入阶段结束
  → 检查成功Cell
  → 生成GeoServer Layer Group
  → 配置GeoWebCache
  → 登记base_maps
  → 完成后处理
```

只有在以下条件满足时执行后处理：

1. 批次状态为`succeeded`。
2. 或管理员明确允许部分成功，且成功Cell达到配置阈值。
3. 默认不允许`partial_failed`替换当前有效底图。
4. 18个目标Cell全部成功或已是最新状态时，才视为完整成功。

任何后处理失败：

- 不回滚已经成功导入的普通S-57数据集。
- 不删除旧的有效底图。
- 不把新底图设为启用。
- 在批次metadata中记录错误。
- 提供“重试底图发布”操作。
- 不需要重新执行ogr2ogr。

首次实现采用按需缓存，不强制全量预生成瓦片。

`warmLowZoomCache=true`时：

- EPSG:3857只预热低缩放级别。
- EPSG:3413只预热低缩放级别。
- 缓存预热作为best-effort步骤。
- 缓存预热失败不使底图导入失败。
- 不在API请求线程执行。
- 支持取消或超时。
- 记录缓存任务结果。

不要一次预生成全部高缩放级别全球瓦片。

# 十七、幂等与更新

重复点击必须安全。

场景：

## 17.1 首次运行

- 创建18个数据集。
- 应用各自完整更新链。
- 生成Layer Group。
- 登记WMTS底图。

## 17.2 再次运行，文件没有变化

- 18个Cell全部`skip_current`。
- 不重复创建dataset。
- 不重复创建dataset_version。
- 不重复复制相同文件。
- 可以跳过导入，仅检查和重建底图配置。

## 17.3 数据包有新更新

- 只为对应Cell追加连续新版本。
- 成功后Layer Group切换到数据集当前有效版本图层。
- 清理或失效旧WMTS缓存。
- 新图层组全部校验成功后才替换旧底图。

## 17.4 更新失败

- 失败Cell保持旧current_version。
- 旧Layer Group和旧WMTS继续可用。
- 新候选底图不得启用。
- 批次显示partial_failed或failed。
- 管理员可以修复文件后重试。
