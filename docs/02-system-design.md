# 极地海洋环境信息平台系统设计

## 1. 设计目标

系统采用模块化单体架构，在保持部署和开发简单的前提下，为未来增加航线规划、S-100产品和正式数据源保留明确扩展点。

设计优先级依次为：数据正确性、权限安全、可追溯性、地图稳定性、可维护性和性能。

## 2. 总体架构

```text
┌─────────────────────────────────────────────────────────┐
│ Vue 3 + TypeScript + Element Plus                       │
│ OpenLayers + Proj4 + ECharts                            │
└──────────────────────────┬──────────────────────────────┘
                           │ HTTPS / REST / WMS / WMTS
┌──────────────────────────▼──────────────────────────────┐
│ FastAPI 模块化单体                                      │
│ auth | users | projects | catalog | imports | maps      │
│ query | exports | demo_sources | audit | system         │
└──────────────┬──────────────────┬───────────────────────┘
               │                  │
┌──────────────▼─────────┐  ┌─────▼──────────────────────┐
│ PostgreSQL + PostGIS   │  │ 同代码库独立 Import Worker │
│ 业务元数据与空间数据   │  │ GDAL/OGR + GeoServer REST  │
└──────────────┬─────────┘  └─────┬──────────────────────┘
               │                  │
┌──────────────▼──────────────────▼───────────────────────┐
│ 本地文件存储             GeoServer + GeoWebCache         │
│ 原始文件/派生文件/日志    WMS/WMTS/WFS/SLD                │
└─────────────────────────────────────────────────────────┘
```

### 3.2 运行进程

一期使用同一后端代码库构建两个进程：

- API进程：处理认证、管理、查询和地图配置接口。
- Worker进程：领取导入任务，运行GDAL/OGR，管理PostGIS派生表和GeoServer资源。

两者通过PostgreSQL任务表协作，不引入消息队列。

## 4. 后端模块

### 4.1 `auth`

- 用户名密码认证。
- Argon2密码验证。
- 访问令牌、刷新令牌和退出。
- 登录失败限制。
- 当前用户上下文。

### 4.2 `users`

- 用户创建、停用、角色修改和密码重置。
- 强制两个角色枚举。
- 防止删除或停用最后一个系统管理员。

### 4.3 `projects`

- 项目生命周期。
- 项目初始范围和默认投影。
- 项目图层配置和发布前校验。
- 普通用户已发布项目读取模型。

### 4.4 `catalog`

- 数据集、版本、文件、空间范围和坐标系元数据。
- 图层、样式、图例和发布信息。
- 同一数据集在多个项目中的复用。

### 4.5 `imports`

- 上传接收和安全校验。
- 导入任务创建、重试、取消和日志。
- S-57基础单元、增量更新顺序和回退。
- S-57批次、源文件和单元结果跟踪；批次Worker编排单元内串行更新。
- GeoTIFF/COG、Shapefile和GeoJSON处理。

### 4.6 `maps`

- 生成前端地图配置。
- 底图、项目图层、投影和GeoServer服务地址。
- 图层样式、透明度、顺序和默认可见性。

### 4.7 `query`

- 要素识别。
- 属性表分页和字段筛选。
- 空间范围限制。
- 查询字段白名单和返回数量限制。

### 4.8 `exports`

- 将筛选结果导出为CSV或GeoJSON。
- 权限、数量和字段限制。
- 导出审计。

### 4.9 `demo_sources`

- AIS演示数据适配器。
- 水文气象演示数据适配器。
- 稳定接口契约，为未来正式数据源实现预留。

### 4.10 `audit` 与 `system`

- 审计事件持久化和管理员查询。
- 请求ID、结构化日志和健康检查。
- 系统配置读取。

## 5. 前端模块

### 5.1 应用框架

- Vue Router：登录、项目、地图工作台和管理页面路由。
- Pinia：认证、用户偏好、项目地图配置和导入任务状态。
- Axios或基于Fetch的统一API客户端：令牌刷新、请求ID和错误转换。

### 5.2 地图引擎

- OpenLayers负责底图、WMS/WMTS、矢量和交互。
- Proj4注册EPSG:3413等自定义投影。
- 地图视图切换时重新构建视图和必要图层，不在不同投影间复用错误瓦片。
- 图层加载错误按图层隔离。

### 5.3 管理端

- 用户管理。
- 项目编辑与发布。
- 数据上传与导入任务。
- 数据集、图层和样式配置。
- 底图和系统配置。
- 审计日志。

### 5.4 普通用户端

- 项目列表。
- 地图工作台。
- 图层树、图例和元数据。
- 要素查询、属性表和导出。
- 测量、截图和打印。
- AIS和气象演示功能。

## 6. 关键业务流程

### 6.1 登录

1. 用户提交用户名和密码。
2. 后端校验状态、密码和失败次数。
3. 返回短期访问令牌，设置刷新Cookie。
4. 前端将访问令牌保存在内存中。
5. 刷新失败时清理会话并跳转登录页。

### 6.2 数据上传和导入

```text
管理员上传
  → 流式写入临时文件
  → 安全与格式校验
  → 创建数据集版本和导入任务
  → Worker领取任务
  → GDAL检查/转换
  → 事务性写入PostGIS或生成派生文件
  → GeoServer REST发布
  → 图层变为可用
```

失败时保留原始文件、错误日志和任务上下文。当前有效版本不得被失败任务覆盖。

### 6.3 S-57 更新

1. 识别海图单元名称和更新号。
2. 锁定对应数据集，避免并发更新。
3. 校验当前有效更新号与新更新号连续。
4. 基于当前有效版本构建候选新版本。
5. 应用增量并进行GDAL完整性检查。
6. 写入候选PostGIS表和GeoServer资源。
7. 校验成功后原子切换有效版本。
8. 失败时删除候选派生资源，保留当前有效版本。

### 6.4 S-57 批量导入

```text
管理员选择ZIP或本地目录
  → API流式保存源文件并创建queued批次
  → Worker安全解包/暂存并扫描三位数字扩展名
  → 按单元名归组并校验连续更新链
  → 匹配已有有效数据集：跳过已应用更新，必要时由本次文件修复缺失历史源，再追加连续新更新
  → 未匹配单元创建独立数据集并从.000开始处理
  → 单元内依次创建并执行新增版本的导入任务
  → 汇总批次进度、成功项和失败项
```

Web请求只接收源文件和创建批次，不执行解压或GDAL。单元之间继续处理，单元内部严格串行；已有数据集必须指向有效版本。导入器只沿当前版本的父版本链读取源文件，忽略孤立的失败候选版本；若祖先源文件丢失，批次必须提供对应更新文件才能修复并继续。批次终态为`succeeded`、`partial_failed`或`failed`。原始批次文件和每个版本源文件均保留以支持追溯。

提交上传的 API 与领取任务的 Worker 必须访问同一份存储根目录。开发前端若代理到本机 API，而 Worker 运行在服务器，将导致服务器找不到本机保存的批次源文件；此时前端 API 代理必须改为服务器应用地址，或在本机同时运行使用同一存储的 Worker。

### 6.5 项目发布前：S-57 图层批量加载与智能筛选

在地图工作台中，用户可以在不展开数据集的情况下选中多个 S-57 数据集，通过"批量加载"功能一次性解析、筛选并分批创建对应的 OpenLayers WMS 图层。

**批量加载（创建 WMS）与批量导入（创建数据库资源）是两个不同的功能，不可混淆。**

批量加载流程：

1. 用户选中一个或多个 S-57 数据集（无需展开）。
2. 选择加载档案（核心海图层 / 推荐海图层 / 全部可显示图层）。
3. 前端调用 `POST /api/v1/projects/{projectId}/map-layers/resolve` 一次性完成权限、当前有效版本、可用性和档案筛选。
4. 系统自动跳过：非空间图层（DSID、C_AGGR）、未发布图层、不可用图层和（非 all_spatial 模式下）未映射样式图层。
5. 可加载图层列表按 `displayPriority → objectClass → id` 稳定排序。
6. 前端以每批 5 层、批间 200ms 的节奏创建 WMS 对象。
7. 单个图层失败不中断其他图层；加载完成显示成功、失败和跳过数量。
8. >40 候选图层需二次确认；>120 直接阻止。
9. 支持取消剩余加载和卸载所选数据集/搜索结果/全部海图图层。
10. 卸载操作不影响底图、AIS 演示、气象、测量和高亮图层。

三种加载档案：

| 档案 | 说明 |
|------|------|
| `core_chart` | 仅加载已映射样式的核心海图层（COALNE、DEPARE、SOUNDG、WRECKS 等 12 种） |
| `navigation_recommended` | 核心海图层 + 航行推荐层（灯标、浮标、分道通航、限制区等 24 种） |
| `all_spatial` | 所有有几何且可发布的图层，含未映射样式图层和可选专题图层 |

**后端分类事实来源**：`backend/app/services/s57_layer_catalog.py` 是 S-57 对象分类的唯一权威来源，前端不复制分类规则。

**图层元数据写入**：新导入 S-57 图层时，`layers.metadata_json["s57"]` 合并分类快照（objectClass、displayCategory、loadProfile、displayPriority、recommended、renderable、styleMapped、featureCount）。旧图层无 s57 元数据时，resolve API 动态调用分类函数，保持向后兼容。

**更新链校验增强**：DK20925C 缺失 .001 → `S57_UPDATE_GAP` + `missingUpdates=[1]`；NO2A0404 缺失 .000 及中间更新 → `S57_BASE_MISSING` + `missingUpdates=[0,..,8]`。不完整链不创建候选版本、不发布 GeoServer 资源。

### 6.6 项目发布

项目配置界面以数据集为逻辑图层单元。保存配置时，API校验数据集未删除、存在当前有效版本且至少有一个可用内部图层，再将该数据集展开为多条`project_layers`记录。地图、GeoServer发布和要素查询继续使用这些物理图层；界面不逐一暴露S-57对象类别。默认显隐应保持关闭，避免一次加载大量WMS请求。

地图配置接口先返回数据集摘要；前端展开一个海图单元时，再读取该数据集的物理`project_layers`作为图层目录项。只有用户显示一个具体图层时才创建对应WMS图层，关闭后释放图层对象和瓦片缓存；因此已配置但默认隐藏的数据集和未展开的内部图层均不参与地图渲染循环。

发布前必须校验：

- 项目名称、默认投影和初始范围有效。
- 至少包含一个可用图层。
- 所有默认可见图层发布成功。
- 样式存在且GeoServer可访问。
- 普通用户地图配置中不包含管理接口和本地文件路径。

### 6.7 要素查询

1. 前端提交图层ID、地图坐标、投影和容差。
2. 后端校验图层已发布及字段白名单。
3. 将坐标转换到数据层坐标系。
4. 使用PostGIS空间索引查询。
5. 返回标准要素摘要和允许属性。

GeoServer `GetFeatureInfo` 可以作为栅格或特定WMS图层的补充，不作为所有查询的唯一实现。

## 7. 投影设计

### 7.1 支持投影

- EPSG:3857：常规Web地图。
- EPSG:4326：数据交换和经纬度坐标。
- EPSG:3413：北极立体投影。

### 7.2 原则

- 数据集版本必须记录原始SRID。
- 未识别坐标系的数据不得直接发布。
- 转换优先由PostGIS或GeoServer执行。
- 前端只执行显示和交互所需的坐标转换。
- 跨越180度经线的数据必须进行专项测试。

## 8. GeoServer 集成

- 使用专用工作区，例如 `polar_gis`。
- 使用GeoServer REST API创建存储、资源、样式和图层。
- 禁止直接修改GeoServer内部配置文件。
- 资源名称使用稳定的内部标识，不使用用户输入名称。
- 图层别名和中文标题通过元数据配置。
- WMS用于渲染，WMTS/GeoWebCache用于缓存，WFS仅在受控场景使用。
- 管理凭据只存在于后端环境变量中，不下发前端。

## 9. S-57 表达策略

一期不实现完整ECDIS内核。采用以下策略：

1. GDAL/OGR解析S-57对象和属性。
2. 将对象按几何类型和对象类别导入PostGIS。
3. 为关键对象类别提供预设SLD样式。
4. 建立S-57对象代码、中文名称、图例和样式映射表。
5. 优先覆盖岸线、陆地、航道、等深线、水深点、灯标、浮标、沉船、障碍物、限制区和锚地。
6. 未配置样式的对象默认关闭，并在管理端提示。

一期内置的预设映射覆盖`COALNE`、`LNDARE`、`DEPARE`、`DEPCNT`、`SOUNDG`、`NAVLNE`/`FAIRWY`、灯标与浮标、`WRECKS`/`OBSTRN`、`RESARE`和`ACHARE`。Worker在发布对应S-57派生图层时自动创建/更新预设SLD并绑定GeoServer默认样式；未命中的对象类标记为`unmapped`，由管理员后续配置。

## 10. 状态机

### 10.1 项目

```text
draft → published → archived
  ↑         │
  └─────────┘ 允许管理员撤回为草稿
```

### 10.2 图层

```text
processing → available
     └────→ publish_failed → processing
available → disabled
```

### 10.3 导入任务

```text
queued → running → succeeded
   │        ├────→ failed → queued（重试）
   └──────→ cancelled
```

### 10.4 S-57 导入批次

```text
queued → running → succeeded
              ├──→ partial_failed
              └──→ failed
```

批次项独立使用`queued/running/succeeded/failed`；批次进度按已完成单元数计算，单元进度按已应用更新文件数计算。

## 11. 错误处理

- 所有API错误返回统一错误结构。
- 业务错误使用稳定错误代码。
- 请求日志包含 `request_id`。
- 导入任务错误区分上传、校验、转换、数据库和GeoServer阶段。
- 前端按全局错误、页面错误、图层错误和字段错误分层展示。
- 外部服务故障不得导致核心项目和海图不可用。

## 12. 安全设计

- Argon2密码哈希。
- 短期JWT访问令牌。
- 刷新令牌存储于HttpOnly Secure Cookie，并在服务端保存可撤销标识。
- 管理接口强制 `system_admin`。
- 上传文件名不作为存储路径。
- ZIP文件检查绝对路径、`..`、符号链接和解压炸弹。
- GeoServer只允许后端管理访问，普通用户访问代理或受控只读服务。
- 导出和上传记录审计日志。

## 13. 性能设计

- PostGIS几何列建立GiST索引。
- 常用筛选字段建立B-tree索引。
- 属性表使用服务端分页。
- 地图使用GeoWebCache缓存稳定图层。
- 大栅格优先转为COG或内部瓦片友好格式。
- 前端图层树和属性表采用虚拟滚动或分页。
- API不得将完整空间表加载到内存。

## 14. 扩展点

后续功能通过模块接口扩展，不改变一期单体原则：

- S-101/S-102解析和表达适配器。
